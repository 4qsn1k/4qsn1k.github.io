# Контекст проекта для продолжения

**Проект:** ЭкзоТека. **Бот:** @ExoTekaBot.  
**Исходники:** GitHub `4qsn1k/4qsn1k.github.io`, каталог `exoteka/`.  
**Рабочий VPS:** `/home/chatgpt-admin/exotic-pets-bot`.  
**Контейнер Docker:** `exoteka-bot`.

## Действующие решения

- Любой пользователь может создать свою коллекцию из `/start` без обращения к администратору сервера.
- Можно присоединиться к семейной коллекции по одноразовой ссылке (48 часов) или коду.
- Личная коллекция сохраняется при присоединении к другой. Активная коллекция переключается.
- Участники видят и изменяют общую историю, а владелец управляет приглашениями и отзывом доступа.
- Все операции со сведениями животных выполняются в пределах активной коллекции.
- На главной — Rich Table со статусами кормления и короткие кнопки. «👥 Семья и коллекции» находятся только в «⚙️ Настройки».
- Интервал кормления вводится числом дней. Добавление животного — в «Управление»; периоды — в «Мои питомцы».
- Отметка «Накормил» требует подтверждения, её можно отменить; удаление карточки заменено архивом.

## Миграция

На рабочем VPS сохранены прежние 10 животных с историей кормлений за 13 октября 2026 года. Ранее допущенный второй пользователь сохранил доступ. Реальные данные и идентификаторы не публикуются в GitHub.

## Как продолжать

1. Изучи README и docs/ARCHITECTURE.md.
2. Проверь рабочий контейнер и состояние базы.
3. Сделай резервную копию SQLite до миграций.
4. Разрабатывай на временной базе, проверь изоляцию 2+ коллекций, права редактора/владельца, срок приглашения и отзыв.
5. После проверки обнови VPS и сохрани код новым коммитом.
6. Никогда не публикуй реальные данные, личные идентификаторы, `.env` и токены.

Фраза для нового чата: «Продолжаем ЭкзоТеку. Рабочая версия на VPS, исходники в GitHub/exoteka. Прочти docs/CONTINUITY.md, проверь базу и контейнер, действуй через MCP и фиксируй безопасные обновления в GitHub».
