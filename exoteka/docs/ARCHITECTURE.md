# Архитектура ЭкзоТеки

Python 3.12, aiogram 3.x, SQLite, Docker Compose.

## Многопользовательская модель

Каждая коллекция имеет уникальный `owner_id`. Таблица `pets.owner_id` остаётся ключом коллекции; идентификаторы существующих животных сохраняются.

- `collections` — коллекции с владельцем и названием.
- `collection_members` — участники (`owner` / `editor`).
- `collection_users` — пользователи и выбранная активная коллекция.
- `collection_invites` — одноразовые приглашения с SHA-256 хешем токена, сроком действия 48 часов и возможностью отзыва.
- `pets`, `feeding`, `feed_confirmations`, `ui_modes` — карточки, кормление, подтверждения, настройки оформления.

`tenancy.TenantMiddleware` устанавливает текущий Telegram ID в контексте обработки каждого события. `bot.owner_id()` возвращает ключ активной коллекции, а не глобальный ID владельца. Запросы к карточкам и изменениям всегда ограничены `owner_id`.

Каждый участник может иметь доступ к нескольким коллекциям, но работает в одной активной за раз. Создание своей коллекции не удаляет семейную; принятие приглашения не удаляет собственную. Только владелец выдаёт/отзывает приглашения и отключает участников. Редактор может управлять животными и кормлением.

При повторном запуске миграция не восстанавливает ранее исключённых участников. Существующая коллекция и история кормлений сохраняются при переходе с однопользовательской версии.

## Навигация

- Для нового пользователя: `/start` → «Создать свою» либо «Подключиться по приглашению».
- Главная: статусы и таблица кормления; «Накормил», «Обновить», «Мои питомцы», «Управление», «Настройки».
- «Настройки» → «Семья и коллекции»: выбор активной, создание личной, ввод ссылки, участники и приглашения.
- «Мои питомцы»: паспорта, индивидуальный период, история.
- «Управление»: создание, редактирование, архивирование и восстановление.

В Telegram используются Native Rich Messages; при ошибке API — классические сообщения.
