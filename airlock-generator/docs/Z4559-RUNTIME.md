## Перед первым реальным подключением

1. На работе подключить **отдельный стендовый ПР100**. Не пользоваться рабочей шиной нескольких устройств и не назначать одновременно два Modbus Master.
2. Определить COM-порт адаптера на Z4559; прежние COM3/9600 8N1/Slave16 относятся к успешному опыту «КПП 2», а не обязательно к этому экземпляру ПР100.
3. Прочитать только DI/Q однократным скриптом `gateway/pr100-readonly-probe.py`; сверить результат с физическими светодиодами. Не выполнять FC05/06/15/16 и не загружать Owen Logic.
4. Подготовить профиль `airlock-connection.json`, задающий протокол, COM/Unit ID и существующие регистры. Не выдумывать `ROOM.State`/герконы, если они отсутствуют в Modbus Slave.
5. Запустить `gateway/preflight.js` и подтвердить структуру профиля. Preflight **не открывает порт** и не доказывает связь с ПР.
6. После успешного подключения вручную проверить `http://127.0.0.1:8787/scada.html`: online/offline, изменения DI/Q, события, истечение времени актуальности. Состояние GREEN не выводится из одних DI/Q.
7. Только после этого можно отдельно обсудить автоматический запуск агента.

## Подготовленные команды запуска агента

Из каталога `airlock-generator`:

```powershell
node .\gateway\preflight.js --config "C:\локальный\airlock-connection.json"
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\start-telemetry-agent.ps1 -Config "C:\локальный\airlock-connection.json"
```

Launcher ищет изолированное Python-окружение `AirlockGeneratorLab\.venv`, проверяет наличие `pymodbus` и `pyserial`, проверяет профиль, затем запускает read-only сервер только на `127.0.0.1`. Внешний доступ возможен только через отдельно согласованный безопасный VPN/туннель.
