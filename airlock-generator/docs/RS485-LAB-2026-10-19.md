# Airlock Generator — подготовка ПР100 / USB-RS485 к испытанию 19.10.2026

## Источник параметров

В прежнем проекте **«КПП 2»** реально работал ПР100 с адаптером Болид USB-RS485. Проверенные настройки **того** подключения: `COM3`, `9600`, `8N1`, Modbus RTU Slave ID `16`, `pymodbus 3.15.0`, `pyserial 3.5`. PowerShell вызывал Python-скрипты `monitor_inputs.py`, `monitor_io.py`, `gateway_monitor.py`; считывались DI и Q, работали живые состояния шлюза. Не предполагать автоматически, что второй экспериментальный ПР имеет те же Slave ID и прошивку.

**Никаких аппаратных действий 18.10 не было.** HOME-PC — основная программная тестовая машина. Настоящий ПР100 и адаптер станут доступны 19.10 на работе.

## Сегодня проверено без физического ПР

- Прямой адаптер **USB-RS485** в `gateway/modbus-rtu.js` + `gateway/modbus-rtu-worker.py`.
- Имеющийся Modbus TCP оставлен без изменений. Для serial-протокола поддерживаются только FC01, FC02, FC03, FC04 — **чтение**.
- Вкладка **Контроллеры** SCADA позволяет выбрать USB-RS485, COM3/9600/8N1, Unit ID.
- Вкладка **Сигналы**: кнопка шаблона ПР100 DI1–DI8 (FC02 адреса 4096–4103) и Q1–Q8 (FC01 адреса 0–7). Это **адреса по прежнему работающему КПП 2**; проверить по паспорту/реальной модификации.
- Данные DI/Q отображаются как **диагностика реальных физических входов и выходов**, не как сигнал разрешения зелёного. Без свежих переменных `State/FireNormal/Closed/BlockRequested/GreenPermit` зелёный шлюза остаётся неподтверждённым.
- Опрос одного COM-порта сериализован, чтобы два контроллера на общей RS-485 не запускали конфликтующие запросы параллельно.
- Ошибки чтения, отключение адаптера и пустая карта сигналов дают `OFFLINE` без удержания прежних данных.

## Минимальный тест 19.10 без изменения ПР

1. Убедиться, что это **отдельный экспериментальный** прибор. Не подключать второй Modbus Master на действующую шину и не перехватывать COM-порт действующего gateway.
2. Подключить RS-485 A/B к Болид USB-RS485 согласно документации обоих устройств. Проверить питание экспериментального ПР100. Не присоединять замки или исполнительную нагрузку.
3. В диспетчере устройств Windows определить актуальный COM-порт. `COM3` — исходная подсказка, а не гарантия.
4. Сверить настройки порта, Slave ID и доступность регистров с проектом/паспортом ПР. **Ничего не загружать в ПР.**
5. Проверить Python:

```powershell
python -V
python -m pip show pymodbus pyserial
```

Если отсутствуют пакеты, установить в локальное окружение, где допускает политика работы:

```powershell
python -m pip install "pymodbus>=3.15,<4" "pyserial>=3.5,<4"
```

6. Скачать отдельно `gateway/pr100-readonly-probe.py` из ветки PR либо перенести файл в локальный каталог с рабочего проекта.

7. В каталоге файла выполнить **однократный read-only запрос**:

```powershell
python .\pr100-readonly-probe.py --com COM3 --unit 16 --baud 9600 --parity N --stopbits 1 --cycles 1
```

8. Если подтверждён ответ Modbus, включить непрерывное чтение с локальным журналом:

```powershell
python .\pr100-readonly-probe.py --com COM3 --unit 16 --baud 9600 --parity N --stopbits 1 --cycles 60 --interval 1.5 --log .\pr100-test-2026-10-19.jsonl
```

Сравнить DI/Q с фактическими светодиодами ПР100 и ранее работающим `gateway_monitor.py`. Менять входные сигналы можно только на изолированном стенде по согласованной безопасной схеме. Записей на ПР скрипт не выполняет.

9. Отключить/вернуть экспериментальный USB-RS485. Подтвердить сообщения OFFLINE/ONLINE и новую актуальную выборку после восстановления.

## Если нужна полная SCADA

На ПК с Node.js и Python, в каталоге проекта Airlock Generator:

- Открыть `scada.html`; выбрать вкладку **Контроллеры → USB-RS485 / Modbus RTU**.
- Указать экспериментальный порт, параметры Slave и таймаут. Для ПР100 на вкладке **Сигналы** нажать «Добавить DI1–DI8 и Q1–Q8».
- Сохранить локальный `airlock-connection.json`. Не добавлять этот файл с реальными адресами площадки в публичный репозиторий.
- Запустить `node gateway/server.js --config "C:\\путь\\к\\airlock-connection.json"`.
- Открыть **http://127.0.0.1:8787/scada.html** — появится вкладка диагностики контроллеров с фактическими DI/Q. Отсутствующие `O_State` и разрешения продолжают отображаться как UNKNOWN.

**Важно:** PowerShell/Python-тест не требует Node.js. Полная SCADA потребует Node.js на компьютере, где находится USB-RS485, или отдельного защищённого канала к этому компьютеру.

## Критерии реального успеха (пока не достигнуты)

- **RTU_LINK_PASS:** подтверждён корректный ответ физического ПР по устройству с указанным Unit ID.
- **IO_READ_PASS:** 8 DI и 8 Q прочитаны и совпадают с ожидаемым состоянием прибора.
- **FAULT_RECOVERY_PASS:** пропажа USB/RS485 и возвращение вызывают предсказуемый переход OFFLINE→ONLINE.
- **SCADA_LIVE_PASS:** реальные значения DI/Q дошли до веб-интерфейса.
- **SHARED_DOOR_LOGIC_PASS:** только после экспорта и проверки сетевых переменных ST/FBD, а не на основании одних физических DI/Q.

Пока ни один из этих результатов **не объявлен пройденным**. Не использовать данные SCADA для управления эвакуацией или дверными замками. Отдельная пожарная цепь остаётся независимой.
