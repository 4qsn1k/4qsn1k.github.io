# Интерактивный стенд Airlock N1 ↔ N4 — 18.10.2026

## Назначение и границы

Страница `../stand.html` представляет **демонстрационный стенд** взаимодействия двух программных помещений N1 (продувка 30 секунд) и N4 (взаимная блокировка). Это самостоятельный веб-интерфейс на GitHub Pages.

Рассчёт выполняет **существующая детерминированная JS-модель** `st-testbench.js` + `interzone-testbench.js` + `project-wiring.js`, управляемая `stand-core.js`. Стенд не обращается к Owen Logic, ПР, СКУД, замкам, АПС, датчикам давления, Modbus или вентиляции. QA-OL-012 на настоящем FBD ведётся отдельно.

## Использование

1. Откройте `https://4qsn1k.github.io/airlock-generator/stand.html` после публикации обновления `main`.
2. Нажмите на любую из шести дверей или карточку геркона. Один клик меняет общий сигнал закрытия/открытия для обеих прилегающих зон.
3. Выберите предустановку **A–F**; нажмите +1 с, +10 с или +30 с, либо включите пошаговое движение виртуального времени.
4. Для проверки NC/NO выберите дверь в блоке светофора. При потере питания ламп выключите соответствующий флажок.
5. При двух открытых дверях может возникнуть зафиксированная авария. Для сброса сперва закройте двери, затем нажмите «Сброс аварии».
6. Экспортируйте JSON журнала. Это только локальные виртуальные события.

## Правило двух цветов на одном DO

Выбран **один DO на один красно-зелёный светосигнальный комплект** при применении перекидного контакта SPDT (встроенного в пригодный ПР либо промежуточного реле):

- COM: защищённая линия питания ламп;
- NC: красная лампа;
- NO: зелёная лампа;
- команда DO/катушки: 1 только при комплексном разрешении зелёного; при 0 — NC.

Для общей двери **1–4** программное разрешение в демонстрационной модели:

`FireNormal AND Closed_1_4 AND NOT (N1.Block_1_4 OR N4.Block_1_4) AND N1.Ready AND N4.Ready`.

**Важные ограничения:** это комбинационная модель, не утверждённая цепь безопасности. Пропадание управления переводит реле к NC только при сохранённом питании ламп. При потере этого питания обе лампы погаснут. Красный при пожаре не является сигналом удержания электрозамка; пожарный выход эвакуации проектируется независимо от логики зелёного.

Условный бюджет по существующей карте `project-wiring.js`: **9 DO** при двух светофорах помещений (6 отдельных логических запретов, 2 ламповых канала, 1 тревога) либо **13 DO** при шести дверных светофорах. Это не окончательное число аппаратных выходов: BUSY, сетевой обмен, объединение реле и внутренние логические сигналы могут уменьшить или изменить потребность в клеммах.

## Известные ограничения

- Встроенная в `stand.html` демонстрационная модель синхронизирована с `model.json` на дату создания. Для произвольных конфигураций генератора пока нет динамического импорта проекта в эту отдельную страницу.
- Скорость виртуального времени приблизительная для демонстрации. JS-модель не подтверждает реальную точность таймера ПР.
- В веб-стенде не моделируются фактические положения контактов, авария обрыва геркона, отклики замка, давление, направление прохода, сбой Modbus и независимое пожарное освобождение.
- Сценарии A–F проверяют **поведение JS-эталона**, а не заменяют нативную QA Owen Logic.
