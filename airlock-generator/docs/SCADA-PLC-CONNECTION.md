# SCADA Airlock Generator — подключение существующего ПР к готовому проекту

**Версия проекта:** прототип 18.10.2026; HOME-PC — основная тестовая машина.

## Принцип работы

Одна конфигурация `airlock-project-scada.json` содержит геометрию и правила шлюза. Вкладки SCADA создаются из неё автоматически, независимо от количества помещений, номеров дверей и выбранных ПР. Второй локальный файл `airlock-connection.json` связывает этот проект с одним или несколькими действительными контроллерами и адресами **чтения**.

```text
                         AIRLOCK GENERATOR
                     проект помещений и дверей
                               │
                  ┌────────────┴─────────────┐
                  │                          │
          ST / FBD / I/O                 SCADA / проект
          логика ПР                      план / сигналы / журнал
                                             │  GET (без команд)
                                             ▼
                                   Локальный шлюз Node.js
                                     127.0.0.1:8787
                                             │ Modbus TCP, FC01–04
                                             ▼
                                 Ethernet / TCP↔RTU конвертер
                                             │ RS-485, Modbus RTU
                                             ▼
                                        ПР100 / ПР200
```

Сайт GitHub Pages является только **редактором проекта**. Его публичная страница не подключается к вашим ПР через интернет. Реальная SCADA запускается на компьютере в защищённой сети с приборами, где открыт локальный шлюз.

## Поддерживаемые варианты

| Прибор | Интерфейс | Подключение этой версии |
| --- | --- | --- |
| ПР100 с RS‑485 (при наличии интерфейса в точной модификации) | Modbus RTU Slave | Преобразователь **Modbus TCP ↔ RTU** с поддержкой MBAP TCP, а не простой прозрачный TCP-канал |
| ПР200 первого поколения | Modbus RTU Slave | Такой же Modbus TCP ↔ RTU преобразователь |
| ПР103 / ПР205 подходящей модификации | Modbus TCP (зависит от модели/прошивки) | Непосредственно по TCP при подтверждении документации и настроек |
| RS-485 через USB-COM | Modbus RTU | **Ещё не поддерживается этим шлюзом**; нужен отдельный serial-адаптер программы |

**Официальная информация:** [сеть ПР100](https://docs.owen.ru/product/pr100/doc/rukovodstvo-po-ekspluatacii-pr100/podklucenia) и [протоколы Owen Logic](https://docs.owen.ru/product/programmnoe_obespechenie_owen_logic/doc/rukovodstvo-polzovatela-owen-logic-versia-26/bazovye-svedenia/rabota-s-makrosami).

## 1. Подготовка ПР — ничего не изменяя

1. Зафиксируйте точную модификацию ПР, прошивку, конфигурацию интерфейса и схему подключения.
2. В Owen Logic или исполнительной документации **прочитайте** режим `Slave`, адрес устройства `Unit ID`, скорость, чётность и количество стоп-битов RS‑485.
3. Найдите существующие сетевые переменные, их Modbus-адреса, типы данных и функции чтения. Никаких адресов «по порядку» не назначайте.
4. Для отображения комнатных `O_State`, `O_Ready`, `O_Fault`, состояния герконов и итогового `GreenPermit` соответствующие переменные должны **уже быть доступны** по Modbus Slave. Если проект их не экспортирует, одна только SCADA не сможет прочитать внутренние ST-переменные. Добавление сетевых переменных требует отдельного изменения проекта Owen Logic, проверки и последующей согласованной загрузки в **испытательный** ПР.
5. Если на RS‑485 уже работает другой Master, не включайте второй опрашивающий Master на ту же шину без согласованной схемы; используйте существующий мастер/шлюз и предусмотренный канал телеметрии.

Только после этих проверок выбирайте конвертер и способ доступа. Скорость и чётность на стороне RS‑485 должны совпадать с ПР. Modbus TCP-порт типично 502, но реальное значение задаётся конфигурацией конвертера.

## 2. Создание профиля в генераторе

1. Откройте [Airlock Generator](https://4qsn1k.github.io/airlock-generator/).
2. Создайте или импортируйте схему помещений и дверей.
3. Нажмите **SCADA проекта** (новая вкладка) либо **Скачать проект SCADA** для переноса.
4. В SCADA откройте **Контроллеры**. Введите `PR1` или свой идентификатор, модель, **IP Modbus TCP ↔ RTU преобразователя** (или ПР с подтверждённым Modbus TCP), порт, Unit ID из Owen Logic, таймаут.
5. В **Сигналы** задайте адреса каждой требуемой переменной. Пример **типа** привязки: `ROOM_1.State` → `PR1` → `FC03` → **нулевой адрес PDU из вашей Modbus-карты**. Не переносите наугад отображаемую запись вида `40001`: её база может отличаться.
6. Для каждой общей двери настройте **одну** переменную `Closed`, итоговый `BlockRequested` и отдельную `GreenPermit`. Состояния обеих комнат тоже должны быть доступны.
7. Скачайте `airlock-connection.json` и перенесите **локально** на компьютер с доступом к ПР. Не добавляйте реальные IP/адреса площадки и файлы с секретами в публичный GitHub.

### Кодирование состояния

`ROOM_X.State` — целое число из программы ПР:
- `10` → READY;
- `20` → OPEN/BUSY;
- `30` → PURGE;
- `90` → FAULT;
- `99` → FIRE.

`DOOR_X.Closed`, `BlockRequested`, `GreenPermit`, `SYSTEM.FireNormal` читаются как `0/1`. Если переменная BOOL отображается в одном бите регистра, настройте верную функцию чтения и адрес бита; произвольное смещение бита из слова не поддерживается текущим декодером. Типы и адреса должны соответствовать опубликованным сетевым переменным Owen Logic.

**Зелёный** на общей двери отображается только при одновременном подтверждении: Closed=1, BlockRequested=0, GreenPermit=1, FireNormal=1, все участвующие зоны READY. При отсутствии любого подтверждения дверь серая (UNKNOWN), не зелёная. Для отсутствующего физического подтверждения замка SCADA не делает выводов о настоящем отпирании.

## 3. Запуск локального шлюза

Нужен Node.js 22+ на HOME-PC или выделенном компьютере рядом с ПР. Сеть должна разрешать TCP к указанному IP конвертера/контроллера.

```powershell
cd "C:\Users\Forest\Documents\AirlockGeneratorBackup\repo\airlock-generator"
node gateway/server.js --config "C:\путь\к\airlock-connection.json"
```

Программа должна сообщить:

```text
AIRLOCK_SCADA_LOCAL http://127.0.0.1:8787/scada.html
```

Откройте в браузере <http://127.0.0.1:8787/scada.html>. Здесь будут страницы **План**, **Контроллеры**, **Сигналы**, **Инструкция**.

Вкладка «Контроллеры» показывает, отвечает ли ПР, и причину ошибки. Смена профиля требует перезапуска шлюза: публичная веб-страница **не записывает** параметры в сервис и тем более в ПР.

## 4. Контроль первой связи

На **отдельном стендовом ПР** или согласованном канале существующего прибора:

1. Проверить доступность IP преобразователя, порт TCP и Unit ID.
2. Сравнить считанное числовое значение одного безопасного регистра с показанием/данными Owen Logic. Затем проверить остальные привязки.
3. Сменить сигнал только на безопасном **испытательном** стенде. Убедиться, что соответствующая карточка SCADA обновилась.
4. Отсоединить стендовую линию связи. Убедиться, что по истечении времени актуальности индикаторы становятся серыми, а не зелёными.
5. Вернуть связь. Убедиться, что статусы восстанавливаются только по вновь полученным данным.
6. Проверить совместную дверь и обрыв одного из контроллеров. При отсутствии любого критического разрешения зелёный не должен подтверждаться.
7. Записать результаты, модель/прошивку ПР, IP подключения (только в локальном защищённом протоколе), время цикла и список реально прочитанных адресов.

Без успешной проверки на настоящем ПР статус **PLC CONNECTIVITY PASS** ставить нельзя.

## 5. Сеть и ограничения

- Шлюз слушает **только** `127.0.0.1:8787`; привязка к `0.0.0.0` запрещена. Для доступа с другого ПК используйте VPN или SSH-проброс локального порта.
- Modbus TCP сам по себе не обеспечивает шифрование или проверку подлинности. Никогда не публикуйте TCP 502 и порт 8787 напрямую в интернет.
- Протокол чтения: только FC01 / FC02 / FC03 / FC04. Код **не отправляет** FC05/06/15/16, не управляет замками, дверями, сбросами аварий, светофорами или пожарной цепью.
- Интервал опроса по умолчанию 1500 мс, истечение актуальности — 5000 мс. Значения настраиваются в локальном профиле, под нагрузку сети ПР требуют проверки.
- Если параметры устройства, порядок регистров, адреса или сетевые переменные ещё неизвестны, SCADA покажет **НЕТ СВЯЗИ/НЕТ ДАННЫХ**. Это корректно и безопаснее выдуманных зелёных.
- Работающий обмен с эмулятором Modbus TCP — ещё не доказательство совместимости конкретной модели ПР. Действующие ПР и реальные цепи не изменялись.

## Оставшиеся инженерные задачи

- **Аппаратный стенд подключения конкретной модификации ПР**: проверить настоящие сетевые переменные и карту регистров.
- Настроить несколько ПР, общий геркон и итоговые разрешения с проверкой сетевых задержек и устаревших данных.
- Перенос профиля и ПО через единый экспортируемый проект, установка локального шлюза как службы, резервное копирование и аудит.
- Добавить опциональный COM/RS‑485-адаптер Modbus RTU при потребности; сейчас поддерживается только Modbus TCP (включая активный TCP↔RTU конвертер).
- Согласовать и испытать независимую аппаратную пожарную цепь, отказобезопасность, обратную связь замка и питание светофоров.

**Граница утверждения:** разработан и протестирован чтение/парсинг по локальному эмулятору; испытание связи с ПР ещё ожидается.
