# Распределение дверей по нескольким ПР — промежуточная спецификация

**Состояние:** 17.10.2026 — распределитель сигналов и симуляция потери связи работают в JavaScript. **Реальных клемм, Modbus-адресов и программ для ПР эта версия не создаёт.**

## Новый экран конструктора

После «Оборудование ПР и расширения» появился раздел **«Размещение сигналов по контроллерам»**. В нём настраиваются:

- `roomOwners` — на каком ПР исполняется `FB_Room_N<room>`.
- `doorInputOwners` — какой ПР физически получает **один геркон** конкретной двери.
- `doorOutputOwners` — какой ПР должен сформировать итоговый **логический запрос** запрета двери после объединения зон.
- `alarmOwner` — контроллер общего сигнала `ANY_ALARM`.

Карта размещения сохраняется в `model.hardware.placements` вместе с JSON проекта. Команда **«Скачать карту сигналов JSON»** экспортирует предварительные слоты и зависимости обмена. Этот JSON не является файлом программы Owen Logic.

### Пример двух ПР103

Предположим, два ПР с проверенными паспортами и достаточными DI/DO. Выбрана сеть Ethernet/Modbus TCP. Разделение зон:

| Сигнал | ПР1 | ПР2 |
|---|---|---|
| Функциональный блок | N1 | N4 |
| Герконы | 1–2, 1–4, 1–5 | 2–4, 3–4, 4–6 |
| Итоговые запреты дверей | 1–2, 1–4, 1–5 | 2–4, 3–4, 4–6 |
| АПС/ResetFault | отдельные **локальные логические DI** | отдельные **локальные логические DI** |
| Светофоры по комнатам | N1 | N4 |
| Общая тревога | ANY_ALARM | передаёт O_Alarm для OR |

Получается **5 DI и 5 DO** на ПР1, **5 DI и 4 DO** на ПР2, если у каждой комнаты один перекидной светофор. Это пример **логической** раскладки, а не подтверждённая клеммная спецификация. При выборе светофора каждой двери расчёт другой. Указанные числа не учитывают резервные каналы, дополнительную обратную связь и согласованный проект электрики.

В примере **общая дверь 1–4** имеет один DI на ПР1. Значение `CLOSED_D_1_4` должно быть доступно блоку N4 на ПР2 только через подтверждённый актуальный канал связи. Запрос `FB_Room_N4.O_D_1_4_Block` поступает на ПР1, где логически объединяется с запретом N1 через `OR`. ПР1 не должен считать отсутствие запроса от ПР2 разрешением прохода.

## Предварительные номера каналов

В экспортируемой карте используются обозначения наподобие `PLC1.BASE.DI1`, `PLC1.PRM1.DO1`. Это **позиции для инженерной проверки**, а не реальные имена клемм или аппаратные адреса. Распределитель:

1. Использует бортовые каналы ПР, затем каналы ПРМ по слотам.
2. Не допускает двойного занятия одного логического слота.
3. Отказывает при нехватке каналов **на конкретном** ПР, даже если их достаточно суммарно.
4. Не допускает неизвестные ПР и не назначенные помещения или двери.
5. Дополнительный `O_VentilationRequest` размещает на ПР соответствующего помещения, только если выбран интегрированный режим.
6. Учитывает состояние обеих зон для зелёного светофора **общей двери**.

Подтверждение реальных электрических характеристик каналов, количества входов конкретной модификации, совместимости ПРМ и монтажные клеммы остаётся обязательным.

## Modbus — пока без физических адресов

Модель выдаёт перечень межконтроллерных переменных с полями `from`, `to`, `signal` и `consumers`. Для удобства сортировки есть `proposedPublisherWordIndex`, но `proposedModbusAddress=null`.

**Необходимо отдельно назначить:** адреса Modbus, роли клиент/сервер, формат BOOL, адресацию zero-based/one-based в Owen Logic, периоды опроса, приоритеты, восстановление после ошибок, heartbeat и тайм-ауты.

Никакие реальные регистры и IP-адреса не записывались. Вентиляционная обратная связь `VentilationComplete` также отсутствует; продолжительность таймера не доказывает продувку.

## Потеря обмена — отдельные тесты

Модуль [`network-watchdog.js`](../network-watchdog.js) воспроизводит **контроль свежести в памяти Node.js**. Тестовый срок годности должен быть введён явно (`timeoutMs`); проектных безопасных значений по умолчанию нет.

Проверяются:
- значение до первого подтверждённого кадра считается неизвестным;
- новый BOOL с последовательным номером кадра и временем обновляет состояние;
- устаревший или повторно присланный кадр **не продлевает** разрешение;
- по истечении тайм-аута логическое разрешение зелёного сбрасывается;
- новые корректные данные могут восстановить свежесть только после полного контроля остальных условий.

**Важно:** «запретить зелёный» — не то же самое, что «запереть замок». При потере сети физические двери и устройства СКУД должны переходить в *утверждённое проектом* состояние; возможность экстренного выхода обеспечивается независимо от программ ПР и Modbus. Питание, АПС, эвакуация, системы вентиляции и нормальные/аварийные сценарии требуют отдельного HAZOP/FMEA или эквивалентного анализа.
