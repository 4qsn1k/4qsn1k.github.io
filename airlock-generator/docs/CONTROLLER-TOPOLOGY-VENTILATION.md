# Архитектура контроллеров, модулей ПРМ и связи — 17.10.2026

## Назначение

Airlock Generator должен создавать проекты для произвольного количества дверей, помещений и контроллеров. Нельзя ограничивать их исходной демонстрационной модификацией ПР100-24.1208.03.1 М02.

### Подтверждённые семейства

| Семейство | ПРМ через внутреннюю шину | Сетевой интерфейс |
|---|---:|---|
| ПР100 | 0 | RS-485/Modbus только при наличии интерфейса в модификации |
| ПР102 | до 2 | RS-485/Modbus, количество зависит от исполнения |
| ПР200 | до 2 | RS-485/Modbus, количество зависит от исполнения |
| ПР103 | до 2 | Ethernet/Modbus TCP; RS-485/Modbus RTU |
| ПР205 | до 2 | Ethernet/Modbus TCP; RS-485/Modbus RTU |

Официальные источники: [ПР100](https://owen.ru/product/pr100/specifications), [ПР102](https://owen.ru/product/pr102), [ПР200](https://owen.ru/product/pr200/specifications), [ПР103](https://owen.ru/product/pr103), [ПР205](https://owen.ru/product/pr205/specifications).

ПРМ-1: 8 DI и 8 релейных DO ([источник](https://owen.ru/product/prm1/specifications)).
ПРМ-5: 16 релейных DO без DI ([источник](https://owen.ru/product/prm5)).
Поддержка ПРМ определяется семейством основного ПР, а тип входов, питание и пригодность каналов для конкретной нагрузки — точным исполнением прибора.

## Как пользоваться новым разделом

В редакторе в панели **«Оборудование ПР и расширения»** доступны:

1. **Семейство ПР**: ПР100, ПР102, ПР200, ПР103, ПР205.
2. **Точная модификация** — текст из заводского обозначения. Не подставлять автоматически значения I/O для другого исполнения.
3. **Бортовые DI и DO** — числовые значения из паспорта конкретной модификации. Для примера ПР100.1208 начально установлено 12/8.
4. **Слот ПРМ №1 и №2** — поддерживается только совместимыми семействами. Пока известны ПРМ-1 (+8 DI/+8 DO) и ПРМ-5 (+16 DO); остальные требуют отдельного проверенного описания.
5. **+ Второй ПР** — добавляет независимый ПР с собственной модификацией и ПРМ.
6. **Связь**: RS-485/Modbus RTU или Ethernet/Modbus TCP. Для RS-485 нужно явно подтвердить наличие интерфейса у каждого устройства; для Ethernet проверяется наличие поддержки у семейства.
7. **Светофоры**: по помещениям или по дверям, одно DO на красно-зелёную перекидную пару.
8. **Дополнительные вентиляционные выходы** для помещений, выбранных как «Совместно со СКУД», учитываются в бюджете DO.

Расчёт показывает суммарно необходимые и доступные DI/DO и остаток. **Проверка достаточности по сумме не является распределением физических клемм**. При разделении зон по нескольким ПР необходимо учесть сетевые переменные, источник общих герконов, функциональные границы и исполнительные модули.

## Важные ограничения

- При работе нескольких ПР генератор **не создаёт сетевую карту регистров**, не назначает роли Master/Slave, сетевые адреса, watchdog и тайм-ауты. Эти задачи остаются TODO.
- При использовании Ethernet/Modbus TCP следует выбирать исполнение с Ethernet. ПР100 и ПР200 не получают встроенный Ethernet только от установки Modbus.
- Не следует автоматически считать транзисторный DO, аналоговый канал и релейный DO взаимозаменяемыми.
- Для общей двери, управляемой несколькими зонами, сетевой обрыв, зависший регистр или задержка должны переводить логические разрешения в проектно утверждённое безопасное состояние. Доступ для эвакуации и пожарное отпирание организуются независимо от сети и программного состояния.
- Программа в Owen Logic должна быть **отдельной на каждом ПР**. Настоящая распределённая компиляция, нативный FBD и сетевой обмен между физическими ПР пока не испытаны.
- Графический калькулятор **не соединяется с оборудованием и не назначает клеммы**. Это инженерный черновик.

## Раздельное управление вентиляцией

Свойство помещения `ventilationControlMode` для `interlockMode=purge`:
- `independent` (по умолчанию): отдельная система вентиляции со своими герконами. Генератор не формирует выход запроса на запуск.
- `integrated`: к FB добавляется `O_VentilationRequest`, который активен в `State=30` при подтверждённом закрытии дверей, нормальной АПС и отсутствии Fault. Это **виртуальный запрос контроллеру вентиляции**, не силовой выход. Физический DO можно назначать только после инженерной проверки интерфейса.

**Таймер ПР100 не равен подтверждению фактического окончания продувки.** Ни в автономном, ни в интегрированном режиме завершение продувки внешним контроллером не подтверждено обратным сигналом. Возможность разблокировки только по таймеру должна быть согласована для конкретного процесса; если нужна обратная связь, потребуется дополнительный вход `VentilationComplete` и контроль тайм-аута/отказа. Этот вход **ещё не реализован**.
