# SCADA — обслуживание COM-порта RS-485 (19.10.2026)

## Назначение

Для экспериментального ПР100 на Z4559 подтверждена физическая связь по CP210x **COM5**, Modbus RTU 9600/8N1/Slave 16, и совпадение считываемых состояний `DI3=1; Q2=Q3=Q4=1` с физической индикацией ПР (пользователь подтвердил на стенде). Это **только read-only аппаратная диагностика**, не проверка логики разрешения дверей.

Поскольку только один процесс должен владеть одним COM-портом, в локальную SCADA добавлено управление владением COM **по аналогии с отключением конкретного порта в ПО «Болид»**. Это позволяет освободить COM5 для UPROG, не завершая весь агент и не отключая опрос других ПР на других интерфейсах.

## Интерфейс

Открыть локально на Z4559: `http://127.0.0.1:8787/scada.html`, вкладка **Контроллеры → Управление COM-портами**.

- **Освободить порт:** после предупреждения принудительно прерывает ожидающие операции, закрывает последовательный worker и **ждёт завершения процесса ОС**. Только после подтверждённого закрытия выводит «Освобождён». Все контроллеры на **общем COM5** сразу переходят `OFFLINE`; DI/Q перестают считаться свежими, `GREEN` не может определяться из них. Другие COM-порты и TCP-контроллеры продолжают работать.
- **Возобновить опрос:** сначала подтвердить, что UPROG и Owen Logic завершили работу с данным портом. Разрешает новые запросы. **До получения свежего успешного ответа данные остаются OFFLINE/NOT_POLLED**, прошлые значения не восстанавливаются из кэша.
- При ошибке или таймауте закрытия worker статус **не выдаёт ложное подтверждение освобождения**. Порт остаётся заблокированным для новых запросов агента; оператор должен проверить состояние.

Управление доступно только в **запущенном локальном агенте** с портами в конфигурации. Статический GitHub Pages не имеет доступа к аппаратным портам.

## Локальный API (ТОЛЬКО обслуживание соединения)

- `GET /api/ports` — список COM с данными `paused/releasing/controllerIds`; выдаёт временный токен подтверждения действий.
- `POST /api/ports/COM5/release` — после подтверждения пользователя освобождает порт.
- `POST /api/ports/COM5/resume` — возобновляет опрос после закрытия сторонней программы.
- Контроль: привязка HTTP только к `127.0.0.1`, строгая проверка Origin и Host, временный токен `X-Airlock-Control`, запрет произвольных COM не из профиля, строго пустое тело запроса, никакого Modbus-записывающего действия.
- HTTP-ответ `200` на release возвращается **после события завершения serial worker**, а не после `kill()`.
- Секретные параметры подключения не возвращаются через `/api/project`. COM-порт виден локальному оператору во вкладке обслуживания.

**Это сервисная операция управления сеансом компьютера**. Она НЕ является отказобезопасной аппаратной блокировкой и НЕ отправляет команды контроллеру на изменение Q, замков или программы. При действующем шлюзе потерю контроля связи необходимо рассматривать отдельно по проекту промышленной безопасности. Данные SCADA — только мониторинг.

## Проверка

Программные автономные испытания `node tests/scada-port-maintenance.test.js`:

1. Запросы нового Modbus Master блокируются, пока старый worker не завершился.
2. Все ПР на одном COM одновременно уходят OFFLINE; независимый TCP-ПР остаётся ONLINE.
3. После resume требуются новые подтверждённые данные, сохранённый ранее GREEN не возвращается.
4. Ответ старого worker после быстрого release/resume игнорируется по поколению запроса.
5. Local API отклоняет чужой Origin, неправильный токен и COM, отсутствующий в профиле.
6. API не меняет правило запрета Modbus FC05/06/15/16.

**Аппаратные действия:** кнопки на настоящем ПР100/COM5 ещё НЕ испытывались. Реальное чтение COM5 и сверка индикаторов — отдельная, ранее подтверждённая проверка. Новые тесты используют подставные процессы, не открывают реальный COM.

## Операторская последовательность

1. Убедиться, что порт занят исключительно экспериментальным агентом и что на нём нет действующей системы безопасности.
2. В SCADA нажать **Освободить порт**, прочесть предупреждение, подтвердить.
3. Дождаться статуса **Освобождён**. Убедиться, что данные соответствующих ПР перешли в OFFLINE.
4. Открыть UPROG и выполнить нужную диагностику на **поддерживаемом этим инструментом оборудовании**. Учитывать, что **Owen Logic для программирования ПР100 обычно использует отдельное прямое USB-подключение**, а не RS-485 COM5.
5. Закрыть UPROG и любую другую программу, владеющую портом.
6. Нажать **Возобновить опрос**, подтвердить; дождаться нового состояния ONLINE и сверить DI/Q.

## Не перепутать

- `COM5` — адаптер CP210x / RS-485 / подтверждённый Modbus RTU ПР100 на данном стенде.
- `COM4` — ранее наблюдавшийся прямой USB ПР100 (Owen Logic). Взаимно заменять эти два соединения без документации нельзя.
- Переключатель ПР100 оставлять в положении «Работа» при штатном опросе; менять программу или выходы не требуется.
- Автозапуск агента Z4559 пока не установлен. Установка/перезапуск службы требуют отдельного решения.
