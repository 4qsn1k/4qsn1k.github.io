# Z4559 — аппаратное испытание ПР100 по Modbus RTU, 19.10.2026

**Важное различие:** реальная связь ПР100 и доставка DI/Q в SCADA подтверждены. Полная аппаратная реализация технологического шлюза, замки, пожарная логика, продувка, реальная конфигурация дверей и независимая проверка электробезопасности **не испытывались**.

## Фактическое оборудование и линия

- Компьютер: Z4559, отдельное рабочее окружение `%USERPROFILE%\AirlockGeneratorLab`.
- Экспериментальный ОВЕН ПР100, питание подано, DIP-переключатель «Работа».
- USB-преобразователь Silicon Labs CP210x, в Windows `COM5`; ранее через этот адаптер UPROG распознавал С2000-2, после чего пользователь переподключил его к ПР100.
- Протокол чтения: **Modbus RTU, 9600 бит/с, 8N1, Slave ID 16**.
- **Только FC02** адреса 4096–4103 (DI1–DI8) и **только FC01** адреса 0–7 (Q1–Q8). Команды FC05/06/15/16 не применялись; программа ПР не загружалась, настройки ПР не менялись.

## Первое подтверждение реального Modbus-ответа

Запущен `gateway/pr100-readonly-probe.py`, один цикл, `--com COM5 --unit 16 --baud 9600 --parity N --stopbits 1 --cycles 1`.

Результат: **ONLINE; exit 0**.

| Сигнал | Прочитанные значения |
|---|---|
| DI1..DI8 | `0 0 1 0 0 0 0 0` |
| Q1..Q8 | `0 1 1 1 0 0 0 0` |

Это ответ физического ПР, но совпадение с фактическими светодиодами, подключённой нагрузкой и электрическими цепями отдельно не подтверждено.

## Испытание повторного открытия COM5

Скрипт `pr100-readonly-probe.py` с десятью циклами и периодом 1,5 секунды, который **на каждом цикле заново открывает/закрывает COM**, показал:
- `ONLINE`: **4/10**
- `OFFLINE`: **6/10** — в том числе `PermissionError(13, Access is denied)` при открытии COM5.
- Во всех успешных чтениях DI/Q совпадали с первой выборкой.

Интерпретация: повторное открытие COM5 в этом сочетании драйвера/программ даёт нестабильность. Это не означает ошибок CRC, неправильного Unit ID или доказанного неисправного преобразователя. Причина временных отказов открытия (драйвер, конкурирующее приложение, задержка освобождения) ещё требует диагностики.

Локальный журнал: `AirlockGeneratorLab\bench-20261019\pr100-com5-10samples.jsonl`. **Не загружать локальные журналы и реальные настройки площадки в GitHub**.

## Испытание persistent-сервиса и SCADA

Создан локальный профиль `AirlockGeneratorLab\bench-20261019\airlock-pr100-com5.readonly.json`, 1 экспериментальный ПР, 16 диагностических привязок, `rtuMode=persistent`, интервал опроса 1500 мс, актуальность 5000 мс, бюджет цикла 7500 мс. `gateway/preflight.js` прошёл `ok:true`. Для `ROOM.State`, `SYSTEM.FireNormal`, `DOOR.Closed/GreenPermit` адреса **не выдумывались и не назначались**.

В изолированном тесте через `gateway/server.js`:

| Проверка | Результат |
|---|---|
| Локальный HTTP SCADA | 200 OK |
| GET `/api/project`, `/api/status`, `/api/events` | Работают |
| Модель в демонстрационном экране | 6 комнат, 8 дверей |
| Выборки агента `ONLINE` | **11/12** |
| Первый цикл | `RTU_UNAVAILABLE`; следующий цикл восстановился |
| Последующие ответы | 11 подряд, цикл приблизительно **60–64 мс** |
| Свежие диагностические значения | `DI3=1`, `Q2=1` |
| Неподтверждённый GREEN | Не отображался (12/12 нет ложного GREEN) |
| Завершение этого теста | `AGENT_CLOSED_SERIAL_WORKER_RELEASED` |

Тест использовал настоящее USB-RS485 подключение ПР, а не имитацию Modbus.

## Живой экран после теста

Позднее **вручную**, не как службу Windows, запущен отдельный экземпляр SCADA:

`http://127.0.0.1:8787/scada.html` — доступен из браузера **на Z4559**.

Проверка локального API показала `source=live`, `PR1_ONLINE=true`, `DI3=1`, `Q2=1`, ответ 62,85 мс; число событий 3; публичные параметры COM устройства в `/api/project` редактированию и выводу не подлежат. Демо-топология не считается реальной схемой испытательного ПР.

Скрипт запуска: `AirlockGeneratorLab\bench-20261019\start-airlock-live-manual.js`. Чтобы штатно остановить этот ручной экземпляр и **освободить COM5**, создайте файл:
```powershell
New-Item -ItemType File -Force "$env:USERPROFILE\AirlockGeneratorLab\bench-20261019\request-stop-live-agent.flag"
```
Агент обнаружит файл, вызовет `app.close()` и освободит последовательного worker. Не запускать UPROG на COM5 одновременно с агентом. Автозапуск Windows **не устанавливался**.

## Текущие статусы и следующие действия

- `REAL_PR100_MODBUS_FC01_FC02_LINK_PASS` — да, **19.10.2026**.
- `SCADA_REAL_IO_TELEMETRY_PASS` — да, read-only диагностические DI/Q, persistent.
- `RECONNECT_AFTER_INITIAL_FAILURE_OBSERVED` — да, после единственного начального RTU_UNAVAILABLE.
- `PORT_REOPEN_STABLE` — **нет**, one-shot 4/10.

- `FULL_AIRLOCK_READY_GREEN_EGRESS_PASS` — не проверено.
