# Owen Logic — RDP и диагностика прерванной симуляции (16.10.2026)

## Подтверждено на Z4559

- На Z4559 пользовательский тестовый проект `Airlock_SIMULATION_TEST.owle` выполнялся в процессе `ProgramRelayFBD.exe`, RDP-сеанс **№2**.
- Дублирующий отключённый RDP-сеанс **№7** завершён по прямому разрешению пользователя. Последующая проверка `quser` показала только один сеанс №2.
- В Windows Terminal Services `MaxConnectionTime = 0`, `MaxIdleTime = 0`, `MaxDisconnectionTime = 0`. Признаков трёхчасового лимита сеанса не обнаружено.
- В журнале `Microsoft-Windows-TerminalServices-LocalSessionManager/Operational` зарегистрированы многократные отключения и повторные подключения в течение минут. Ошибка Windows **64** (`0x80070040`): «Указанное сетевое имя более недоступно». Данные соответствуют потере сетевого транспорта RDP; сама причина транспорта (клиентский Интернет, туннель, UDP/TCP, оборудование, политики промежуточной сети) **не определена**.
- В более поздней проверке `quser` показывал один **отключённый** сеанс №2; `GetForegroundWindow()` возвращал нулевой дескриптор (`HWND=0`). В этом состоянии ввод в GUI через мост заблокирован.
- Завершение лишнего сеанса №7 не устранило сам сетевой разрыв.

## Влияние на автоматизацию Owen Logic

Мост использует **Windows UI Automation**. Он способен читать сигналы из WPF ST-редактора даже при проблемах с RDP, но не должен нажимать на экран, когда интерактивный рабочий стол недоступен. Это преднамеренное ограничение, а не ошибка симулятора.

Добавлены:
- [focus-owen.ps1](../bridge/focus-owen.ps1) — выводит **только тестовый** Owen Logic на передний план, если рабочий стол интерактивно доступен.
- [qa006_run.ps1](../bridge/qa006_run.ps1) — воспроизводимая последовательность открытия/закрытия и контроль 30-секундного таймера. Операции и фактические показания сохраняются локально в `qa006-latest.jsonl`. Сценарий **не объявляет PASS**, если чтение недоступно или окно неактивно.

## Следующий план

1. Восстановить RDP-сеанс №2 (не создавать новый отдельный сеанс). Запустить Owen Logic в нём, включить режим симуляции ST-блока `FB_Room_N1`.
2. Проверить сигнал через `owen-bridge.ps1 -Action status`.
3. Установить `I_D_1_2_Closed=FALSE`, если ещё не открыт, затем запустить `qa006_run_v3.ps1` из `AirlockGeneratorTest`.
4. Убедиться в показаниях `State=30` после каждого закрытия и `State=20` после повторного открытия во время продувки. Проверить до 30 с, затем после 30 с. Только тогда фиксировать QA-OL-006 = PASS.
5. Для диагностики RDP: сравнить журналы клиента и сервера в момент отключения, исследовать транспорт туннеля/UDP, потери пакетов и тайм-ауты маршрута. Не изменять сетевые политики/службы предприятия без отдельного согласования.

**Не завершать сеанс №2 и не программировать реальный ПР100 без согласования.**
