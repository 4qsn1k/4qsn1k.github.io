# Автоматические проверки Airlock Generator без RDP

**Создано:** 16.10.2026. Работает независимо от Windows и подключения к Z4559.

## Где выполняется

На GitHub размещён workflow [`airlock-generator-qa.yml`](../../../.github/workflows/airlock-generator-qa.yml). Он запускается при изменениях файлов `airlock-generator/**`, при pull request или вручную (`Actions → Airlock Generator QA (headless) → Run workflow`), **если GitHub Actions разрешён в настройках репозитория**.

Ссылка на страницу: https://github.com/4qsn1k/4qsn1k.github.io/actions/workflows/airlock-generator-qa.yml

Задание выполняется на **runner GitHub с Node.js 22**. Рабочий компьютер, RDP и собственный VPS не нужны. Если компьютер выключен, GitHub Actions всё равно может обработать новые коммиты, поступившие в GitHub, но он **не может прочитать несохранённые файлы с выключенного ПК**.

## Что проверяет

1. Синтаксис `st-generator.js`, `st-testbench.js` и `bridge/headless-qa.js`.
2. Набор существующих тестов конструктора: генератор, давление и блокировки, HMI, магнитное совмещение стен.
3. Восемь сценариев автономной JavaScript-модели: стартовая продувка, открытие, повторная продувка, тревога после 30 с, одновременное открытие, пожарный режим, `mutual` и генерация ST.
4. Сохраняет `latest.json`, `latest.md` и датированный JSON-отчёт в артефакте `airlock-model-qa` на странице исполнения workflow.

Если хотя бы один тест завершится ошибкой, задание получает статус FAIL. При успешном тестировании — PASS.

## Испытания

На Z4559 команда:

```powershell
node "$env:USERPROFILE\Desktop\AirlockGeneratorTest\headless-model\bridge\headless-qa.js"
```

Проверена **после исправления сценария восстановления АПС**. Получено `MODEL_QA_FINAL PASS 8/8`. Это относится именно к независимой модели JavaScript.

**Первоначальный прогон был FAIL 7/8:** ожидался `State=0` после восстановления пожарного входа, но моделирование с шагом 100 мс включает несколько внутренних циклов и уже успевает перейти в `State=30`. Исправлен только тест и добавлено ожидание полной 30-секундной продувки, чтобы проверять конечное поведение.

## Важное ограничение

Это **не симулятор Owen Logic**. Система проверяет эталонную JavaScript-модель и синтаксические/структурные свойства сгенерированного ST. Она не запускает Owen Logic, не компилирует ST в ОВЕН, не проверяет электрические цепи и не управляет ПР100.

Валидация на реальном компиляторе и в штатном симуляторе Owen Logic проводится отдельно в [журнале QA](../docs/QA-OWEN-2026-10-16.md).

## Запуск вручную из любого клона GitHub

```bash
cd airlock-generator
node bridge/headless-qa.js
```

Отчёты по умолчанию: `bridge/reports`. Их не следует коммитить в исходники — лучше сохранять только как артефакты workflow или локальные файлы.
