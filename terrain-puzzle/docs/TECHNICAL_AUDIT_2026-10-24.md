# Terrain Puzzle — технический аудит 6 генераторов 3D-карт
Дата: 24 октября 2026. Статус: завершён исследовательский этап; внедрение выполняется по отдельным проверяемым этапам.

## Область проверки
Шесть продуктов: [TerraPrinter](https://terraprinter.com/), [MapsTo3D](https://mapsto3d.com/app.html), [TopoSaic](https://toposaic.com/), [Map2Model](https://www.map2model.de/), [TouchTerrain](https://touchterrain.geol.iastate.edu/main), [PrintNexus](https://printnexus.io/tools/3d-map-maker). Сравниваются исходные данные, точность, геометрия, печать, удобство интерфейса, сохранение и экспорт.

Источники доказательств: публичные сайты и FAQ; открытые исходники TopoSaic и TouchTerrain; инспекция доступных элементов интерфейса веб-сервисов через Microsoft Edge/Playwright; тест HTTP-ответов DEM в точке Белорецка; собственные тесты Terrain Puzzle. **Исходный код закрытых генераторов не изучался, обхода защиты не было.** Экспорт STL конкурентов и физическая печать их пазлов не проводились. Поэтому производительность и качество физических соединений в этой версии аудита не оценены инструментально.

## 1. Данные

| Инструмент | Высоты (DEM) | Дополнительные данные | Механизм |
| --- | --- | --- | --- |
| TerraPrinter | Copernicus GLO-30 (DSM), Mapzen fallback | OSM — здания, вода, дороги, тропы | Геоданные → высотное поле → топография, слои и пазлы → STL/3MF/OBJ/GLB в браузере |
| MapsTo3D | AWS Terrain Tiles, резерв Mapterhorn | OSM; GPX/KML/GeoJSON, здания/линии/точки | Клиентская обработка и экспорт STL, 3MF, OBJ/GLB, DXF |
| TopoSaic | Mapzen и Mapterhorn, в региональных зонах повышенная детализация | ESA WorldCover 10 м, OSM (Overpass, Nominatim), Sentinel-2 | Rust core/API + React/Tauri; локальные SQLite/кэш; детерминированная геометрия |
| Map2Model (.de) | Mapterhorn | OSM, GPX | Клиентский экспорт STL и многокомпонентного 3MF |
| TouchTerrain | Google Earth Engine либо пользовательский GeoTIFF | Пользовательские растры | Проекция UTM, адаптивная дискретизация, генерация сетки в Python |
| PrintNexus 3D Map Maker | Mapzen / AWS | OSM | Клиентские STL/цветной 3MF; простой/расширенный UI |

**DEM — геометрия высот; OpenStreetMap — дороги, контуры рек и объектов; WorldCover — классификация земного покрова, НЕ высоты.** Нельзя достоверно определить лес по абсолютной отметке высоты. Copernicus GLO-30 является цифровой моделью поверхности (DSM), которая может включать растительность и сооружения. Mapzen объединяет несколько исходных DEM. Mapterhorn предоставляет Terrarium-кодированные 512px WebP плитки и PMTiles.

Для Terrarium PNG/WebP: `height_m = R*256 + G + B/256 - 32768`. Кодирование с дробной частью — *числовая точность записи*, а не реальная точность геодезических измерений.

### Реальный HTTP-тест (53.9600 N, 58.3000 E)
* Mapzen Z10–Z15: HTTP 200, PNG 256×256; Z16 HTTP 404.
* Mapterhorn Z10 и Z12: HTTP 200, WebP 512×512; Z13–Z16 HTTP 404.
* CORS `Access-Control-Allow-Origin: *` получен у доступных плиток обоих поставщиков.
* Вывод: нет подтверждения данных высокого разрешения Mapterhorn для этого квадрата. Заменять источник вслепую нельзя.

Страница источника: https://mapterhorn.com/data-access/ ; coverage: https://mapterhorn.com/coverage/ ; лицензии: https://mapterhorn.com/attribution/ . Mapzen: https://github.com/tilezen/joerd/blob/master/docs/attribution.md . Copernicus: https://registry.opendata.aws/copernicus-dem/ . ESA: https://esa-worldcover.org/en/data-access .

## 2. Пайплайн построения
1. Пользователь выделяет геообласть (WGS84), поворачивает рамку/определяет контрольные точки.
2. Координаты приводятся к метрам: локальная проекция для малого участка, полноценная проекция UTM для корректного метрического масштаба. Обеспечить обработку 180-го меридиана и полярных зон.
3. Выбор лучшего DEM по покрытию, исходному пространственному разрешению, правам, целостности и доступности. Растры загружаются по тайлам/COG в кэш. Тайлы z/x/y сами по себе НЕ указывают точность первичного DEM.
4. Объединённое поле высот строится *для всей площади макета*. Неверные пиксели и выбросы определяются и исправляются с сохранением общей границы между сегментами.
5. Для каждого объекта OSM/GPX координаты преобразуются в ту же метрическую проекцию, а высота Z определяется выборкой высотного поля.
6. Слои реки, дороги, зданий, леса не подменяются цветом, вычисленным только по высоте. Непечатные линии расширяются до управляемой минимальной ширины сопла.
7. Поверхность триангулируется; добавляются основание, боковые грани и детерминированные общие кривые пазов. Соседние детали должны иметь одинаковую высоту на шве.
8. Контроль геометрии: неориентированные и дублирующиеся грани, manifold/watertight, нормали, размеры XYZ, зазор соединений, объём/площадь и коллизии.
9. Экспорт: STL — геометрия без цвета; стандартизованный 3MF — отдельные объекты/материалы с проверкой в выбранном слайсере; ZIP с координатами, лицензиями, журналом, планом печати.
10. 3D-предпросмотр строится из того же поля высот/геометрии, что и STL, с управляемой LOD. Печатная карта может включать векторные горизонтали и OSM-подписи.

Код TopoSaic демонстрирует принципы: отдельные Rust core/API/UI; edge profile из общего seed, выборка соседних тайлов по общим координатам, отдельный geoid/vertical reference, despike до генерации, защищённый кэш с манифестом данных, контроль watertight. См.:
* https://github.com/theatrus/toposaic/blob/main/docs/architecture.md
* https://github.com/theatrus/toposaic/blob/main/crates/toposaic-api/src/elevation.rs
* https://github.com/theatrus/toposaic/blob/main/crates/toposaic-core/src/jigsaw.rs
* https://github.com/theatrus/toposaic/blob/main/crates/toposaic-core/src/heightfield.rs
* https://github.com/theatrus/toposaic/blob/main/docs/color-output-plan.md
* https://github.com/theatrus/toposaic/blob/main/docs/slicer-3mf-import.md

## 3. Интерфейс и удобство: сравнительные наблюдения

| Сервис | Лучше всего | Ограничение в нашем сценарии |
| --- | --- | --- |
| TerraPrinter | Настройки принтера и соединений, многоплиточные задания, зазоры, магниты, маркировка, ссылки на проект | Очень большая плотность контролов |
| MapsTo3D | Поворот/формы рамки, GPX/KML/GeoJSON, отдельные экспортируемые слои | Большое количество функций требует упорядочения |
| TopoSaic | 3D рядом с картой и параметрами; сохранение состояний; кэш и воспроизводимый ZIP | Для конечного пользователя установка; настольная зависимость |
| Map2Model | Разделы Model / Layers / Addons; сохранение проекта; понятная модель размера | Продвинутые опции распределены по вкладкам |
| TouchTerrain | Числовые инженерные настройки, UTM, локальные GeoTIFF | Требуется больше технических знаний |
| PrintNexus | Basic / Advanced, небольшое число первичных решений, моментальный preview | Для больших и сложных объектов нужен расширенный режим |

Наблюдения сделаны по DOM в Edge (публичные страницы; не каждый сценарий проходился до экспорта). Это **экспертная эвристика**, не статистическая оценка пользователей.

### Выбор для Terrain Puzzle
* **PrintNexus:** простой стартовый экран; переключатель «Базовый / Экспертный».
* **MapsTo3D:** поворот и свободная форма рамки, импорты GPX/KML/GeoJSON, независимые 3MF-части.
* **TerraPrinter:** профили принтера, управление зазором пазла, штифты/магниты/маркировка, повторяемые задания большой сетки.
* **TopoSaic:** обработка выбросов, общий height frame для всего макета, устойчивый кэш, манивест данных, тестирование топологии, 3MF.
* **TouchTerrain:** UTM и GeoTIFF пользователя; управление выборкой DEM.
* **PrintNexus Topographic Maker:** ступенчатый контурный стиль как *отдельный режим*, не вместо истинно плавной поверхности.

| P1 | Пазлы без пользовательского выбора геометрии и теста зазоров | 3 стиля кромки, gap 0,1–0,4 мм, маркировка и калибровочный тест |
| P1 | Нет сохранения проекта и продолжения печати большой сетки | Project JSON + manifest/cache, очередь задач по плиткам |
| P2 | Бумажная A0 карта — преимущественно рельефные цвета | Векторные горизонтали, подписи, легенда, OSM-слои, лицензии и тест печатного масштаба |
| P2 | Нет собственного облачного вычисления для очень больших заданий | Web Workers и/или локальная Rust/WASM сборка, загрузка чанками, аварийное возобновление |

**Критическое предупреждение:** если смешивать высоты из разных наборов, нужно учитывать вертикальную систему отсчёта (например EGM96 / EGM2008), иначе на границе могут появиться ложные ступени. Источники TopoSaic хранят эту метаинформацию; наш текущий модуль её не нормализует.

## 6. План работ по приоритетам

### Этап A — доверие к данным и точность (P0)
- Ввести `ElevationProvider` с метаданными, источниками Mapzen, Mapterhorn, Copernicus GLO-30 (при доступности) и импортом локального GeoTIFF.
- Реализовать выбор источника по доступному пространственному разрешению с ограничениями лицензии, NoData, vertical datum и географического покрытия.
- Построить совместное высотное поле с контролем границ и корректной проекцией.
- Автоматические тесты одного, соседних 2×2 и 6×6 фрагментов на общую кромку и геометрию.

### Этап B — географические объекты (P1)
- Импорт GPX/KML/GeoJSON, рендеринг маршрута SUP над рельефом без провалов/отрыва.
- Вода и дороги из OSM; контроль скорости Overpass и ошибок.
- Отдельные детали для цветного 3MF.

### Этап C — физический большой пазл (P1)
- Параметры соединений, отверстия под штифты и магниты, маркировка снизу, монтажная рамка.
- Испытание тестового соединения из двух распечатанных деталей PETG/PLA.
- Истинно возобновляемая пакетная выгрузка всех плиток.

### Этап D — высококачественная топокарта и UX (P2)
- Basic/Advanced режим, разделение панели, рабочие профили проектов, история изменений.
- Слои карты и раздельное управление их видимостью в STL, 3MF, 3D и PDF.
- Для A0: векторные горизонтали и надписи, исходные растры без искусственного восстановления деталей; печатные метки/легенда/атрибуция; проверка вывода 100%.

## 7. Минимальные приёмочные тесты

1. На Белорецке проверить доступность Mapzen и Mapterhorn, отчёт о выбранном источнике и качество покрытия; не интерпретировать 404 как «в регионе нет высот».
2. Сгенерировать 2×2 и 6×6 с общим datum, сравнить каждую пару точек на шве (разность высот в пределах плавающей точности до добавления технологического зазора).
3. Проверить на каждом STL две инцидентные грани на ребро, ориентированные нормали, положительный объём, XY ≤ лимита стола.
4. Проверить GPX на слоистом рельефе, маршрут через два/три шва, отсутствие разрывов после сборки.
5. Проверить импорт и цвета 3MF в OrcaSlicer / Creality Print и фактическое назначение цветов, не только наличие ZIP.
6. Сверить PDF A0 MediaBox 841×1189 мм, расчётную географическую шкалу, по возможности векторные горизонтали и атрибуцию.
